# Changelog

All notable changes to `yuan/admin-core` are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the package uses [SemVer](https://semver.org/).

## [Unreleased]

### Added
- Package scaffold: Testbench test suite on in-memory SQLite, Pest 5 with arch hygiene rules, Larastan level 8 (no baseline) and Pint with strict types.
- Package auto-discovery (`AdminCoreServiceProvider`) and `config/admin-core.php`.
- Module registry (`Yuan\AdminCore\Registry`): discovers the core and project module roots, validates every `module.php` (spec §3.1), fails boot on duplicate slugs or names, registers module providers, migrations and routes (`/admin/{slug}`, `{slug}.`, configured base middleware; `superadmin_only` routes require `admin-core.superadmin`).
- `admin-core.modules.disabled` turns off non-core modules of the core root.
- `modules:cache` / `modules:clear` (hooked into `optimize` / `optimize:clear`) and `modules:list`.
- `PageResolver`: `{Name}::{Page}` from `resources/js/pages` (case-exact), `App::` pages, `admin-core.pages.overrides`, and `viteEntry()` for `@vite` preloading; `resolvePage()` for the client.
- `MenuBuilder`: grouped, ordered, permission-filtered menu (`MenuGroupData` / `MenuItemData`).
- `admin:doctor`: npm dependencies against `admin-core.npm.json`, module cache state, environment sanity.
- Dependencies: `laravel/framework ^13.0`, `inertiajs/inertia-laravel ^3.0`, `composer/semver ^3.4`, `spatie/laravel-data ^4.23`, `spatie/laravel-typescript-transformer ^3.3`.
- Shared Data objects (`#[TypeScript]`): `AuthData`, `UserData`, `MenuGroupData`, `MenuItemData`, `AppData`, `FlashData` (native Inertia flash), `PaginatedData<T>` with `PaginationMetaData` / `PaginationLinksData`; `PaginatedData::fromPaginator()` keeps the query string.
- `Http\Middleware\HandleInertiaRequests`: shares `auth`, `menu`, `app` as Data objects; projects extend it to add props.
- `UPGRADE.md` with the standard upgrade steps.
- Audit core (`Yuan\AdminCore\Audit`, spec §7.1): `AuditEvent` taxonomy (labels, badges, fixed log names); `Audit::record()`, `Audit::batch()` (shared `batch_uuid`, nested batches join the outer one) and `Audit::actingAs()` (explicit causer for jobs); `LogsModuleActivity` model trait with `auditLabel()`; `AuditContext` (web / cli / queue); `Masker` with `admin-core.audit.masked_fields` (omit / partial / full) applied to `attribute_changes` and `properties`; append-only `ImmutableActivity` (`ImmutableAuditException`); auth listeners for `login`, `logout`, `login_failed`, `login_locked`, `password_reset`.
- Core migration `create_activity_log_table` (spatie v5 columns + `batch_uuid` + indexes); projects don't publish the spatie stub.
- `ModuleRegistry::forClass()` and `ModuleDefinition::customActions()` / `STANDARD_ACTIONS`.
- Dependency: `spatie/laravel-activitylog ^5.1`. The package forces its activitylog settings (activity model, write action, no buffering, default log name `system`).
- RBAC core (`Yuan\AdminCore\Permissions`, spec §6): `Level` (spatie Role with `label`, `description`, `is_protected`; `Level::superAdmin()`), `HasLevel` user trait (`assignLevel()` with a batched `level_changed`, `level()`, `isSuperAdmin()`; `assignRole` / `removeRole` / `syncRoles` / `givePermissionTo` / `syncPermissions` throw), `PermissionSynchronizer` + `permissions:sync`, `PermissionMatrix` (build, save with the dependency rule, one batched `permissions_updated`, `LevelPermissionsUpdated` event), `GuardRailViolation`.
- Guard rails: always ≥1 active Super Admin; the protected level is immutable; a level with users can't be deleted (checked before spatie detaches anything).
- Session revocation on deactivate, level change and password change through `users.session_version` (raised atomically; a session is valid only while the version it stored at login matches, on any session driver) plus a rotated remember token; stored `sessions` rows are deleted on the database driver. Core migration `replace_sessions_invalidated_at_with_session_version` replaces the earlier timestamp column, which let a session signed in during the same second as a revocation survive it.
- Middleware aliases `active` (`EnsureUserIsActive`; projects also append it to the `web` group, guests and `logout` pass through), `superadmin` (`EnsureSuperAdmin`) and `permission` (spatie); `Gate::before` passes Super Admin.
- `Auth\AuthenticateUser` for `Fortify::authenticateUsing()`: inactive accounts are refused at login with `login_failed` (reason `inactive`).
- `ImmutableActivity::visibleTo($viewer)` (SA visibility rule) and the `HasActivityHistory` model trait.
- `AuthData` gains `level` (`LevelData`) and `permissions` (Super Admin: every synced permission); `PermissionMatrixData` / `PermissionMatrixRowData`.
- `AdminCoreSeeder` (idempotent; `admin-core.seed.password` / `ADMIN_SEED_PASSWORD`, required in production) and `admin:create-superadmin`.
- Core migrations `create_permission_tables` and `add_admin_columns_to_users_table` (`username`, `is_active`, `last_login_at`, soft deletes). Login stamps `last_login_at`.
- Failed and locked logins resolve the account from the identifier, so the SA visibility rule can hide attempts on Super Admin accounts.
- Dependency: `spatie/laravel-permission ^8.3`.
- `Testing\ContractAssertions`: the runtime contract checks of spec §9.1, run over the current app's modules (projects call them from `tests/Feature/ContractTest.php`).
- `Testing\ModuleAssertions`: module test helpers `actingAsLevelWith()`, `actingAsSuperAdmin()`, `assertGuestRedirected()`, `assertForbiddenWithout()`, `assertAudited()` (with masked-field checks) and `assertNotVisibleToNonSuperAdmin()`.
- `Audit\NotAudited` attribute: the opt-out from `LogsModuleActivity`, with a required reason.
- PHPStan rules for controllers, registered by `extension.neon` (projects include `vendor/yuan/admin-core/extension.neon`): `InertiaPropsRule` (Inertia props must be Data objects, scalars or Inertia prop wrappers of those; identifier `adminCore.inertiaProps`) and `RequestInputRule` (no `all()`, `validated()` or key-less `input()`; identifier `adminCore.requestInput`).
- Auth pages `Core::Auth/{Login,ForgotPassword,ResetPassword,ChangePassword}` with `AuthLayout`, `AuthCard`, `FormField`, `PasswordInput` and their Data objects (`Data\Auth\*`); `ResetPasswordData`, `UpdatePasswordData`.
- `Auth\PasswordRules`: spec §8 rules (min 10, mixed case, number; `admin-core.passwords`) set as `Password::defaults()`, with a hint text.
- `Http\ErrorPages`: 403 / 404 / 419 / 500 / 503 as `Core::Errors/Show` (`ErrorPageData`); `admin-core.routes.home`.
- `Testing\ArchRules`: filesystem helpers for the arch tests of spec §9.1 (module namespaces, isolation map, source scans).
- Theme stylesheet `resources/css/admin-core.css` (ui-design §1): light/dark tokens, Tailwind mapping, named type steps and control heights, shadow and overlay tokens, Geist / Geist Mono (projects install `@fontsource-variable/geist` and `@fontsource-variable/geist-mono`).
- Frontend: shadcn primitives moved into the package and restyled (`components/ui`), `usePermission()` / `<Can>`, `lib/format.ts` (id-ID), `useT()` translation helper with `id` / `en` dictionaries, `<Icon name>`.
- `Core::Page` page namespace for the package's own pages (`admin-core.pages.core_path`), server and client.
- `AppData.maintenance_banner` from `admin-core.maintenance_banner` (`ADMIN_MAINTENANCE_BANNER`).
- Generated `resources/icons/lucide.json` (`bin/lucide-icons.mjs`).
- Layout shell: `AdminLayout` (rail, item panel, mobile sheet, topbar, breadcrumbs, user menu, theme toggle, maintenance banner), `PageHeader`, `CommandPalette` (`cmdk`), flash `Toaster`, theme switch in the user menu; `BreadcrumbData` / `BreadcrumbsData`; `AppData.route`; `MenuItemData.create_href`.
- Server-side lists (`Yuan\AdminCore\DataTable`): `DataTableModel` + `HasDataTable` (search, exact filters, sorts, default sort; the model's builder becomes `DataTableBuilder`, so `Model::query()->visibleTo($user)->dataTable($request)` returns a typed paginator), `per_page` limited to 10/25/50/100 (default 25); an undeclared sort or filter is a 400. `Model::dataTableState($request)` builds the `table` prop (`DataTableStateData`, `DataTableFilterData`, `OptionData`). Dependency: `spatie/laravel-query-builder ^7.3.6`.
- `HasVisibilityScope`: the `visibleTo($user)` data-scope hook, no-op by default (models override `applyVisibility()`); `ContractAssertions::assertVisibilityScope()` requires it on every module model.
- Trash (`Yuan\AdminCore\Trash`): `Trash::delete()` (soft delete in one transaction and one audit batch, flashes "Dipindahkan ke Sampah" with an undo for Super Admin), `Trash::restore()` / `forceDelete()`, and `TrashController::routes(Model::class)` for a module's Super Admin Trash (`{slug}.trash`, `.trash.restore`, `.trash.destroy`) rendering `Core::Trash/Index`. `SelectionData` (bulk ids), `TrashItemData`, `TrashPageData`, `UndoData`; `FlashData` gains `description` and `undo`.
- Frontend: `DataTable<T>` with typed columns, `DataTableToolbar` (search, filter chips, Reset, column menu kept in `dt_cols:{slug}`), `DataTablePagination`, page-scoped selection and bulk delete, row menu, loading / empty / no-results / error states; `useTableQuery` (URL state); `EmptyState`, `StatusBadge`, `ConfirmDialog` (optional item name, cancel and secondary action), `ForceDeleteDialog`; the toaster's "Urungkan · 8" action; `Checkbox` indeterminate state; `DialogContent` `hideClose`.
- Forms (frontend-behavior §6): `TextField`, `TextareaField`, `SelectField`, `ComboboxField`, `RelationSelect` (module `lookup` routes answering `LookupData`), `DateField` (shadcn Calendar on `react-day-picker` + `date-fns`, typed `dd/mm/yyyy`, optional time), `NumberField` / `CurrencyField` (id-ID display, either notation pasted), `SwitchField`; `FormFooter`, `FormErrorSummary`, `UnsavedChangesGuard`, `StaleUpdateDialog`, `DetailGrid`, `useAdminForm`; `ui/popover`, `ui/calendar`; `lib/format` gains `formatLocalDate()`, `formatLocalDateTime()`, `parseLocalDate()`, `parseNumber(text, decimalDot)`; NumberField shows on blur how the input was read. npm: `@radix-ui/react-popover`, `react-day-picker`, `date-fns`.
- `Concurrency\PreventsStaleUpdates`: an integer `lock_version` column raised on every update; `updateUnlessStale($attributes, $loadedVersion)` compares it under a row lock and throws a 409 `StaleUpdateException` on a mismatch.
- Module UI dictionaries: `Dictionaries` interface, `ModuleDictionary<'slug'>`, `registerMessages()`; `t()` keys are checked by `tsc` across core and modules.
- Downloads (`Yuan\AdminCore\Exports`, spec §7): `ExportManager::for(Export::class, $request)` (stream up to `admin-core.exports.queue_threshold` (`ADMIN_EXPORT_QUEUE_THRESHOLD`, default 5000), one `exported` audit row per real download (HEAD requests and `Sec-Purpose` / `Purpose: prefetch` requests get an empty 204), Inertia requests sent to the same URL as a plain download; above it a `QueuedExport` row and `ExportJob`), `ModuleExport` base class (modules implement `row()`; the final `map()` neutralizes formula-like text cells against CSV/formula injection), `ExportStatus`; `exports` table (core migration), `model:prune` removes expired rows and files; `DataTableBuilder::dataTableQuery()`; shared `downloads` prop (`DownloadsData::ready_count`) and the topbar `DownloadsLink` badge polled every 30s; DataTable `download` button. Config `admin-core.exports` and `admin-core.attachments`.
- `PageHeader`: the actions wrap below a title that doesn't fit (no more mid-word breaks on phones).
- `Validation\VisibleRecord`: a foreign key must point at a live record the signed-in user may see (`visibleTo()`), for every relation field.
- `ModuleAssertions::assertScopedToUser()` with `DataTable\VisibilityScope` (records `visibleTo()` calls only while a test asks).
- Core `Users` module (`/admin/users`, frontend-behavior §8.1): list (search, Level and Status filters), create, show, edit (`updateUnlessStale`), activate / deactivate, reset password (generated, shown once through `FlashData::secret`, or set by the admin), soft delete + Trash, download. Super Admin accounts are invisible to other levels (`applyVisibility()`, 404 on every route) and only a Super Admin can give the Super Admin level; nobody deactivates, resets or deletes their own account (`UserAccounts::refuseSelf()`, Super Admin included); usernames can't contain `@`.
- The swappable core User model `Yuan\AdminCore\Modules\Users\Models\User` (config `admin-core.models.user`); the project's `App\Models\User` extends it. Module migration adds `must_change_password`, `lock_version` and indexes to `users`.
- User form extension (spec §2.2): `admin-core.users.form_extension` names a `Users\UserFormExtension` (fields as `ExtraFieldData`: text, number or select; rules per field); the Users forms, validation (`extra.*`), `UserData::extra` (`ExtraValueData`) and the detail page pick them up. - Core `Levels` module (`/admin/levels`, Super Admin only, frontend-behavior §8.2): list with user counts, create / edit (`lock_version` on `roles`, core migration) / delete (refused while users hold the level; the protected level is never editable), and the Hak Akses page with the `PermissionMatrix` component (grouped, collapsible rows, row and column toggles, the View dependency rule with hints, changed cells, search, sticky save bar, leave-page guard). `Level` is audited under `log_name` `levels`; `PermissionMatrixRowData::group`, rows ordered by menu group.

- Events `UserCreated`, `UserLevelChanged`, `UserDeactivated` and `ExportCompleted`, dispatched after the commit.
- `DataTableFilterData::column` (hidden) filters on a column other than the key, such as `roles.id`; `LogsModuleActivity::auditLogName()` overrides the log name.

### Changed
- Projects' `App\Models\User` now extends the core User model, and the starter kit's settings profile page, its FormRequest and `Account\PasswordController` are replaced by the core account pages (`AccountRoutes::register()`).
- `Trash::delete()` reports the rows it actually deleted (a model whose `delete()` is refused isn't counted or offered for undo); nothing deleted flashes the error "Tidak ada data yang dihapus." instead of a success toast.
- `AdminCoreSeeder` sets `must_change_password` on the seeded Super Admins outside the `local` and `testing` environments.
- `ModuleRegistry::forClass()` also matches a model's parent classes, so a project model that extends a core module's model belongs to that module.
- Login accepts a username or an email in one field (`AuthenticateUser::credentials()`); the failed-login audit resolves the account the same way.
- `module.php` `icon` must be a lucide icon name from `resources/icons/lucide.json` (was: any kebab-case string).
- Base admin route middleware is now `web, auth, active`; superadmin_only modules use the `superadmin` middleware instead of `can:admin-core.superadmin`.

### Fixed
- `LogsModuleActivity` no longer stores attributes with an `encrypted` cast; the trait read them decrypted, so they reached `attribute_changes` in plain text.
